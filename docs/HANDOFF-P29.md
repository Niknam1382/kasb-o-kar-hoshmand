## ۵) چک‌لیستِ جابه‌جاییِ پوشه (این را مو‌به‌مو انجام بده)
1. **`pg_dump` بگیر:** `docker compose exec -T db pg_dump -U postgres -Fc kasbokar > قبل-از-انتقال-$(date +%F).dump`
   (فایلِ `.dump` در گیت نیست؛ بیرونِ مخزن نگهش دار.)
2. **`.env` را کپی کن** (در گیت نیست ⇒ با `git clone` منتقل نمی‌شود). مهم‌ترینِ مقدار:
   **`ENCRYPTION_KEY` باید دقیقاً همان بماند** — اگر عوض شود، هیچ توکن/رازِ ذخیره‌شده‌ای
   بازخوانی نمی‌شود و باید از نو ثبت شوند. `backup_*.sql` و `*.dump.gz` را هم اگر داری کپی کن.
3. **نامِ پروژهٔ داکر قفل شده است** (`name: kasb-o-kar-hoshmand` بالایِ compose) ⇒ حجمِ
   `kasb-o-kar-hoshmand_postgres_data` بدونِ توجه به نامِ پوشهٔ جدید همان حجمِ قبلی است.
   اگر این خط را برداری یا با `-p` نامِ دیگری بدهی، داکر یکِ دیتابیسِ **خالیِ** تازه می‌سازد
   و همه‌چیز «پاک شده» به‌نظر می‌آید (داده در حجمِ قدیمی سالم می‌ماند).
4. در پوشهٔ جدید: `docker compose up -d db` → صبر تا healthy → `docker compose build bot` →
   `docker compose up -d bot` → `docker compose ps` و `/health`.
   (پوشهٔ git همان پوشهٔ داخلیِ `kasb-o-kar-hoshmand` است؛ از والد `git status` نگیر.)
5. اگر نامِ پوشه را عوض کردی و `name:` را هم عوض کردی، برایِ بازیافتِ داده:

   با `pg_restore` برگردان و `scripts/verify_audit_chain.py` را اجرا کن.
