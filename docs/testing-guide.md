# راهنمایِ تست

دو نوع تست داریم:
۱. **خودکار (Docker)** — درگاهِ اصلیِ کیفیته. هر تغییری فقط وقتی «تاییدشده» حساب می‌شه که این‌ها پاس شده باشن.
۲. **دستیِ تلگرام** — یه جلسه‌یِ دسته‌ایِ کلیک‌کردن با رباتِ واقعی؛ چیزهایی که با رباتِ فیک معلوم نمی‌شن
   (رفتارِ مدلِ واقعی AI، ظاهرِ پیام‌ها، پرداختِ واقعی). چک‌لیستش پایینه.

---

## ۱) تست‌هایِ خودکار

### اجرا (ویندوز، CMD یا PowerShell)
```
cd <مسیرِ مخزن>\kasb-o-kar-hoshmand   # همان جایی که docker-compose.yml هست
docker compose build
docker compose stop bot              # P24: با رباتِ روشن، سوئیت رویِ TRUNCATE قفل می‌کند
docker compose run --rm bot alembic upgrade head
docker compose run --rm bot python3 tests_manual/run_all_tests.py
docker compose up -d bot             # بعد ازِ اجرا برگردان
```
- `docker compose build` **حتماً** بعد از هر تعویضِ فایل‌ها (کد موقعِ build توی ایمیج کپی می‌شه؛ بدونش تست‌هایِ قدیمی اجرا می‌شن).
- خروجیِ سالم: آخرِ خروجی «✅ همه‌ی فایل‌هایِ تست با موفقیت پاس شدن» و یه جمع‌بندی از تعدادِ فایل/تست.
- **آخرین عددِ تاییدشده: ۵۲ فایل / ۳۰۴ تست** (Docker، ۲۰۲۶-۱۰-۰۷). **عددِ انتظارِ فعلی (W1 + W2 + W3 + W4): ۵۹ فایل / ۳۷۰ تست** (و `alembic upgrade head` باید به `d4a9c6e2b8f1` برسه؛ آخرین Docker-تاییدشده: ۵۶/۳۳۱). اگه عددِ قبلی رو دیدی یعنی zipِ جدید جایگزین نشده یا build نشده.
- یه فایلِ تکی: `docker compose run --rm bot python3 tests_manual/run_one.py test_crm.py`
  (P22: هر دو دستور رویِ دیتابیسِ جدا `kasbokar_test` اجرا می‌شوند؛ اجرایِ مستقیمِ فایلِ تست رویِ
  `kasbokar` با پیامِ فارسی متوقف می‌شود، چون `reset_database()` همه‌یِ جدول‌ها را خالی می‌کند
  و تنظیماتِ پنلِ ادمین را از بین می‌برد. اگر جایی عمداً خواستی رویِ دیتابیسِ دیگر اجرا کنی:
  `RESET_DB_CONFIRM=1`.)
- مایگریشن‌هایِ سالم: بعد از `alembic upgrade head` آخرین خط باید به `c4f8a2d6b9e1` برسه (`docker compose run --rm bot alembic heads` فقط یه head نشون می‌ده).
- **قبلِ اجرایِ سوئیت، سرویسِ `bot` را خاموش کن** (`docker compose stop bot`، بعد ازِ اجرا
  `docker compose up -d bot`). تست‌ها جدول‌ها را `TRUNCATE` می‌کنند و رباتِ روشن همزمان رویِ
  همان جدول‌ها می‌خواند ⇒ قفلِ متقابل و گیرکردنِ اجرا در میانهٔ سوئیت (این دقیقاً یکِ اجرا را
  در P24 خراب کرد). هیچ volume mount رویِ `/app` نیست، پس «build قبل از run» شرطِ همان اجرا هم هست.

### اگه چیزی fail شد
فقط این رو برایِ دستیار بفرست: **اسمِ فایلِ fail‌شده + ۲۰–۳۰ خطِ آخرِ خروجیِ اون فایل** (با دستورِ «یه فایلِ تکی» بالا بگیر). لازم نیست حدس بزنی.
- اگه چیزی که تغییر نداده بودیم fail شد، **«flaky» فرض نکن**؛ دوباره اجرا کن و اگه تکرار شد یعنی واقعیه و باید کامل بررسی بشه.
- خطایِ اتصال به دیتابیس (`connection refused`): `docker compose ps` ← سرویسِ `db` باید Up باشه؛ `docker compose up -d db` و ۱۰ ثانیه صبر.

### تست‌ها چطوری کار می‌کنن؟
- هر فایل یه برنامه‌یِ مستقله (`tests_manual/test_*.py`) که دیتابیس رو خالی می‌کنه، فروشگاه/ربات می‌سازه، و **آپدیت‌هایِ تلگرامیِ جعلی** رو از
  داخلِ dispatcherِ واقعی رد می‌کنه. رباتِ فیک (`FakeSession` توی `harness.py`) همه‌یِ پیام‌ها/دکمه‌ها/ویرایش‌ها/فایل‌هایِ ارسالی رو ثبت می‌کنه.
- هوش مصنوعی هم جعلیه (`FakeAi` توی `phase4_helpers.py`)؛ هیچ پولی خرج نمی‌شه و اینترنت لازم نیست.
- `run_all_tests.py` همه‌یِ فایل‌ها رو یکی‌یکی اجرا می‌کنه و تعدادِ «✅ test_…» هر خروجی رو می‌شمره.
- بررسیِ استاتیک (بدونِ Docker): `python3 scripts/check_gates.py` — `check_refs` (ارجاعِ شکسته)، `check_attrs` (ویژگیِ ناموجود)، `lint_names`، `check_callbacks` (P24: هر `callback_data` باید هندلر داشته باشد)، `check_prompt_buttons` (پ۱۰۸: هیچ «🔘 دکمه»ای که ربات در متن/پرامپت نام می‌برد نباید در کیبوردها غیروجود داشته باشد) و `check_text_hygiene` (P24: نویسهٔ سیریلیک/CJK/هانجی داخلِ متنِ فارسی). از P24 رویِ ویندوز هم اجرا می‌شود (کدِ صفحهٔ فرزندها به `utf-8` قفل شد؛ قبلاً با `cp1252` می‌ترکید).

## ۲) چک‌لیستِ دستیِ تلگرام (جلسه‌یِ دسته‌ای)

**آماده‌سازی**: ربات اصلی + یه رباتِ فروشگاهیِ تستی (از @BotFather) + یه کلیدِ AIِ واقعی توی «🔑 تنظیمات کلیدها» یا «🔑 استخرِ کلیدهایِ AI»
+ دو حسابِ تلگرام (یکی «فروشگاه‌دار»، یکی «مشتری»؛ ادمین = آیدیِ تو توی `ADMIN_TELEGRAM_IDS`). یه مبلغِ کوچیک توی کیف‌پولِ فروشگاه‌دارِ تستی بذار.
برایِ هر مورد فقط تیک بزن؛ اگه چیزی عجیب بود، عکسِ صفحه + نامِ مورد رو بفرست.

### الف) ثبت‌نام و اتصالِ ربات
- [ ] `/start` ← ثبت‌نام ← دریافتِ کد (حالتِ `test` یا واقعی) ← ورود موفق.
- [ ] «🔑 ثبت/ویرایش توکن ربات»: توکنِ نامعتبر رد می‌شه؛ توکنِ درست پذیرفته می‌شه و رباتِ فروشگاه جواب می‌ده.
- [ ] اعتبارِ آزمایشی اضافه شده؛ «💰 کیف‌پول» موجودی و تاریخچه رو درست نشون می‌ده.

### ب) محصول، آموزش، پیش‌نمایش
- [ ] «📦 محصولات»: افزودنِ محصول با عکس/قیمت/موجودی؛ ویرایش؛ حذف؛ «📤 خروجی اکسل»؛ ایمپورتِ اکسل.
- [ ] «🧠 دستور هوشمندسازی» و «📢 کانال دانش‌افزایی» ذخیره می‌شن.
- [ ] «👀 پیش‌نمایش ربات»: به سوالِ محصول درست جواب می‌ده؛ رایگانه (موجودی عوض نمی‌شه)؛ «🔚 پایان پیش‌نمایش» کار می‌کنه.

### ج) رباتِ فروشگاه (مشتری)
- [ ] `/start`، چتِ عادی: جوابِ فارسیِ مرتبط؛ هزینه‌یِ چت از کیف‌پولِ فروشگاه‌دار کم می‌شه.
- [ ] پیامِ پشتِ‌همِ سریع: یه جوابِ واحد (debounce).
- [ ] ارسالِ عکس و صدا (اگه کلید/مدلش رو داری).
- [ ] سفارشِ چتی: «می‌خوام X رو بخرم» ← مشتری باید **خودش تایید کنه** (دکمه‌یِ تایید/لغو) ← بعد اعلان به فروشگاه‌دار.
- [ ] فروشگاه‌دار از ربات اصلی سفارش رو تایید/رد/«در حالِ آماده‌سازی/ارسال/تکمیل» می‌کنه؛ مشتری اعلانِ درست می‌گیره؛ موجودیِ محصول درست کم/برگردونده می‌شه.
- [ ] کیف‌پولِ خالی: مشتری «این فروشگاه فعلاً در دسترس نیست» می‌بینه؛ فروشگاه‌دار اعلانِ اتمامِ کیف‌پول می‌گیره.

### د) سبدِ خرید و کمپین (فازِ ۳)
- [ ] مشتری از دکمه‌ها محصول به سبد اضافه/کم می‌کنه؛ با AI («دو تا از X رو بردار / سبد رو خالی کن») هم می‌شه؛ «خالی‌کردنِ کلِ سبد» دکمه‌یِ تایید می‌خواد.
- [ ] «📝 سوال‌هایِ چک‌اوتِ سبد»: فروشگاه‌دار سوال‌ها رو عوض می‌کنه؛ مشتری موقعِ تسویه همون‌ها رو می‌بینه.
- [ ] چک‌اوت ← اعلانِ گروهیِ سفارش به فروشگاه‌دار ← تایید/ردِ گروهی.
- [ ] «🎯 کمپین‌ها»: ساختِ کمپین (نام، نوع، مقدار، کد، حداقلِ سبد، مدت، سقف) ← مشتری کد رو توی سبد می‌زنه ← تخفیف درست محاسبه می‌شه؛ کدِ اشتباه/منقضی/سقفِ مصرف خطایِ مناسب می‌ده؛ «اعلامِ کمپین» به مشتری‌ها می‌ره؛ آمارِ کمپین درسته.
- [ ] «📣 پیام به مشتری‌ها»: پیش‌نمایش ← تایید ← مشتری‌ها پیام می‌گیرن؛ فروشگاه‌دار گزارشِ «ارسال شد به X نفر» می‌گیره.
- [ ] گزارشِ شبانه (ادمین ساعتش رو تنظیم می‌کنه): پیامِ آمارِ امروز می‌رسه.

### ه) پرداخت‌ها
- [ ] شارژِ کیف‌پول با زرین‌پال (کوچک، واقعی یا sandbox) و کارت‌به‌کارت (مبلغِ منحصربه‌فرد، تاییدِ ادمین).
- [x] **بله‌پیِ سفارش‌ها — اولین تراکنشِ واقعی** (مبلغِ خیلی کوچیک): «💳 پرداختِ آنلاینِ سفارش‌ها» (توکنِ فروشگاه‌دار) ← مشتری لینک رو می‌گیره ← پرداخت ← سفارش «پرداخت‌شده» علامت می‌خوره. ✅ انجام شد (۱۴۰۵-۰۸-۱۱، ۱٬۰۰۰ تومان — جزئیات در `TEST_RESULTS.md` §۱۹). ⚠️ چیزی که هنوز با پولِ واقعی دیده نشده: «شارژِ کیف‌پول» از مسیرِ بله‌پی و خودِ زرین‌پال.

### و) فازِ ۴ — خلأِ دانش و پرسش‌وپاسخ
- [ ] از رباتِ فروشگاه چیزی بپرس که توی اطلاعاتش نیست (مثلاً «ساعتِ کاریِ جمعه؟»). انتظار: ربات مودبانه می‌گه به فروشگاه‌دار می‌سپاره و **هیچ `[[GAP]]`ای دیده نمی‌شه**.
- [ ] «🧩 سوال‌هایِ بی‌جواب»: همون سوال با شمارنده‌یِ ۱ هست؛ دوباره (با نگارشِ کمی متفاوت) بپرس ← شمارنده ۲ (نه ردیفِ جدید).
  - اگه ثبت نشد: احتمالاً مدلت دستور رو رعایت نمی‌کنه (در `docs/ai-production-guide.md` بخشِ ۷) — فقط ثبت نمی‌شه، خطرناک نیست؛ بگو تا بررسی کنیم.
- [ ] «✍️ پاسخ بده» ← جواب (>۵۰۰ حرف رد می‌شه) ← پیش‌نمایش ← «✅ ذخیره کن». حالا همون سوال رو از رباتِ فروشگاه بپرس ← با جوابِ تو جواب می‌ده.
- [ ] «📚 پرسش‌وپاسخ‌هایِ تاییدشده»: مشاهده، ✏️ ویرایش، ⏸ غیرفعال (ربات دیگه ازش استفاده نکنه)، 🗑 حذف، ➕ افزودنِ دستی، صفحه‌بندی.
- [ ] «🙈 نادیده بگیر» یه سوال رو از فهرست برمی‌داره.
- [ ] ادمین: «تنظیمات» ← «🧩 خاموش‌کردنِ تشخیصِ سوال‌هایِ بی‌جواب»؛ بعدش سوالِ تازه ثبت نمی‌شه؛ «📜 گزارشِ ممیزی» تغییر رو نشون می‌ده.
- [ ] گزارشِ شبانه خطِ «🧩 N سوالِ بی‌جوابِ جدید» رو فقط وقتی N>۰ داره.

### ز) فازِ ۴ — CRM
- [ ] «👥 مشتری‌ها»: تعدادِ هر بخش درسته (چندتا مشتریِ تستی با تعدادِ سفارش‌هایِ مختلف بساز). بخشِ «جدید» برایِ تازه‌واردها؛ «وفادار» بعد از ۳ سفارشِ موفق.
- [ ] کارتِ مشتری: نام/آمار/سفارش‌هایِ اخیر. «✍️ یادداشت» (بیش از ۱۰۰۰ حرف رد می‌شه)، «🏷 برچسب‌ها» (بیش از ۵ تا یا بلندتر از ۲۰ حرف رد می‌شه)، «🗑 پاک‌کردن».
- [ ] «📣 پیام به این بخش»: فقط مشتری‌هایِ همون بخش پیام می‌گیرن (تعدادِ پیش‌نمایش = تعدادِ بخش).
- [ ] «🧠 خلاصه‌یِ هوشمند»: ابتدا هزینه‌یِ تخمینی نشون داده می‌شه ← «✅ بله، بساز» ← خلاصه‌یِ فارسیِ معقول ← هزینه‌یِ دقیق در «💰 کیف‌پول» (دلیلِ «خلاصه‌یِ هوشمندِ مشتری») ثبت شده. کیفیتِ خلاصه‌ات قابلِ قبوله؟
- [ ] با کیف‌پولِ خالی دکمه‌یِ خلاصه خطایِ «موجودی کافی نیست» می‌ده و چیزی کم نمی‌شه.

### ح) فازِ ۴ — دستیار و حسابداری
- [ ] «💬 دستیارِ مدیریتی»: «امروز چقدر فروختم؟» / «پرفروش‌ترین محصول؟» / «چندتا سفارش منتظرِ منه؟» ← جواب با عددهایِ درست (با «🧮 حسابداری» مقایسه کن).
- [ ] ازش بخواه «سفارش‌ها رو تایید کن» ← **نباید هیچ سفارشی تغییر کنه** (فقط می‌گه از کدوم دکمه انجام بده).
- [ ] چند پرسشِ پشتِ‌هم (حافظه)؛ «🔚 پایان» یا زدنِ هر دکمه‌یِ منو از گفتگو خارج می‌کنه؛ هر پرسش هزینه‌یِ نمایش‌داده‌شده رو کم می‌کنه (دلیلِ «دستیارِ مدیریتی»).
- [ ] «🧮 حسابداری»: امروز / ۷ روز / ۳۰ روز / ماهِ شمسی؛ جمعِ فروشِ خالص با جمعِ سفارش‌هایِ تاییدشده‌ات می‌خونه؛ «📤 اکسلِ این بازه» فایل رو می‌ده (برگه‌هایِ خلاصه/سفارش‌ها/محصولات/کمپین‌ها/روزانه) و **اسم/تلفن/آدرسِ مشتری توش نیست**.
- [ ] ادمین (سوپرادمین): «📤 دفترِ کیف‌پول (اکسل)» فایل می‌ده؛ ادمینِ عملیاتی این دکمه رو نمی‌بینه.

### ط) ادمین
- [ ] تنظیمِ کلیدها، قیمت‌گذاری (محاسبه‌یِ خودکار)، کانالِ اجباری، طرح‌ها، کدِ تخفیف.
- [ ] سوییچ‌ها: حالتِ تعمیر (مشتری‌ها پیامِ تعمیر می‌گیرن)، ثبت‌نام، شارژ، زرین‌پال/بله‌پی، گزارشِ شبانه.
- [ ] مدیریتِ ادمین‌ها (RBAC)، اصلاحِ کیف‌پول (با دلیل؛ در ممیزی ثبت)، نگهبانِ محتوا (BLOCK/WARN/REVIEW)، گزارشِ ممیزی.
- [ ] تایید/ردِ پرداختِ کارت‌به‌کارت.

### ی) خطا و لبه‌ها
- [ ] هر دکمه‌یِ قدیمی (بعدِ ری‌استارتِ ربات) یا «کهنه» پیامِ مودبانه می‌ده، نه خطا.

## اجرایِ تست‌ها با `.env`ِ واقعی
تست‌هایِ ادمین آیدیِ `12345` را فرض می‌کنن. `run_all_tests.py` خودش `ADMIN_TELEGRAM_IDS=12345` را به هر تست می‌دهد (متغیرِ محیطی بر `.env` غالب است)، پس می‌تونی `.env`ِ واقعی‌ات (با توکن‌ها و آیدیِ ادمینِ خودت) را نگه داری. اگه تکی اجرا می‌کنی: `docker compose run --rm bot python tests_manual/run_one.py test_xxx.py` (همان دو متغیرِ محیطی را خودش می‌دهد).
