# کسب‌وکار هوشمند (Smart Business)

پلتفرمِ چندمستأجریِ (multi-tenant) SaaS برای فروشگاه‌های تلگرامی. هر فروشگاه‌دار
با یه ربات تلگرامیِ اختصاصیِ خودش (که با توکنِ خودش ثبت می‌کنه) صاحبِ یه فروشگاهِ
هوشمند می‌شه که با هوش مصنوعی به مشتری‌ها جواب می‌ده، سفارش/مشاوره تشخیص می‌ده،
موجودی رو کم می‌کنه، و گزارش می‌گیره — همه از طریقِ یه ربات مدیریتیِ مرکزی
(«ربات اصلی») که فروشگاه‌دارها باهاش کار می‌کنن.

## معماریِ کلی

```
                    ┌─────────────────────┐
   فروشگاه‌دارها  →  │   ربات اصلی (main)   │  →  ثبت‌نام، پرداخت، مدیریتِ محصولات،
                    │   یه توکنِ ثابت      │      تنظیماتِ فروشگاه، آمار
                    └─────────────────────┘
                              │
                    هر فروشگاه‌دار یه توکنِ
                    ربات مجزا ثبت می‌کنه
                              ↓
   ┌───────────┐    ┌───────────┐    ┌───────────┐
   │ رباتِ شاپِ  │    │ رباتِ شاپِ  │    │ رباتِ شاپِ  │  ← مشتری‌های نهایی این‌جا
   │  فروشگاهِ ۱ │    │  فروشگاهِ ۲ │    │  فروشگاهِ ۳ │    باهاش چت می‌کنن
   └───────────┘    └───────────┘    └───────────┘
```

سه سطح: **ادمینِ پلتفرم** (مدیریتِ کلِ سیستم از طریقِ ربات اصلی) → **فروشگاه‌دار**
(صاحبِ یه فروشگاه، از طریقِ ربات اصلی پنلش رو مدیریت می‌کنه) → **مشتریِ نهایی**
(با رباتِ اختصاصیِ فروشگاه چت می‌کنه، نه با ربات اصلی).

### پشته‌ی فنی
Python 3.12 · aiogram 3 (فریم‌ورکِ ربات، هم polling هم webhook) · FastAPI +
Uvicorn (برای حالتِ webhook) · PostgreSQL + SQLAlchemy 2 (async) + Alembic ·
Zarinpal (درگاهِ آنلاین) + کارت‌به‌کارت (تاییدِ دستی) · هر سرویسِ AI سازگار با
OpenAI API (چت، تحلیلِ تصویر، رونویسیِ صدا).

## شروعِ سریع (لینوکس/مک)

```bash
git clone <این-ریپازیتوری>
cd kasb-o-kar-hoshmand
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# .env رو باز کن و مقادیرِ لازم رو پر کن (حداقل: DATABASE_URL، MAIN_BOT_TOKEN،
# ADMIN_TELEGRAM_IDS، ENCRYPTION_KEY)

# ساختِ یه کلیدِ رمزنگاریِ تازه:
python3 -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

# اجرای مایگریشن‌ها روی دیتابیسِ PostgreSQL (باید از قبل بالا باشه و دیتابیسش ساخته شده باشه):
alembic upgrade head

# اجرا (حالتِ polling، ساده‌ترین حالت برای تستِ محلی):
python3 -m app.main
```

برای ویندوز، اسکریپتِ `scaffold.ps1` همینِ مراحل رو خودکار انجام می‌ده — به
بخشِ «راه‌اندازیِ محلی روی ویندوز» پایین‌تر نگاه کن.

## شروعِ سریع با Docker (پیشنهادی برای تستِ محلی)

اگه نمی‌خوای پایتون/PostgreSQL رو دستی نصب کنی، همه‌چیز (دیتابیس + ربات) با
Docker Compose بالا میاد:

```bash
cp .env.docker.example .env
docker compose build
docker compose run --rm bot python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
# مقدارِ چاپ‌شده رو توی .env جلوی ENCRYPTION_KEY= بذار، و MAIN_BOT_TOKEN/ADMIN_TELEGRAM_IDS رو هم پر کن
docker compose up
```

مایگریشن‌ها به‌صورتِ خودکار موقعِ استارت اجرا می‌شن (نیازی به دستورِ alembic
دستی نیست). راهنمای کاملاً مصورِ گام‌به‌گام (برای کسی که هیچ پیش‌زمینه‌ی فنی
نداره) توی `docs/docker-quickstart-guide.md` هست.

## ساختارِ پروژه

```
app/
  config.py              # تنظیمات (از متغیرهای محیطی، با pydantic-settings)
  main.py                 # نقطه‌ی ورود: FastAPI app + حالتِ polling/webhook
  database/
    models.py              # همه‌ی مدل‌های SQLAlchemy (۱۷ جدول)
    session.py              # engine + session factory
  bots/
    common/                 # میدل‌ورهای مشترک بینِ ربات اصلی و ربات‌های فروشگاهی
    main_bot/                # ربات مدیریتی: فروشگاه‌دارها + ادمین
      handlers/
        start.py               # ثبت‌نام، گیتِ کانال، پیشنهادِ آزمایشی
        panel.py                # پنلِ فروشگاه‌دار: اشتراک، پرداخت، پروفایل
        products.py             # مدیریتِ محصولات (شاملِ موجودی)
        admin.py                # پنلِ ادمین: کاربران، پرداخت‌ها، تنظیمات، قیمت‌گذاری
    shop_bot/                # ربات فروشگاهی: مشتری‌های نهایی
      handlers/customer.py     # چت با AI، عکس/صدا، تشخیصِ سفارش، debounce
  services/                # منطقِ کسب‌وکار (۳۰ فایل، بدونِ وابستگی به aiogram)
  utils/                   # رمزنگاری، اعتبارسنجی، کدِ معرف
migrations/                # Alembic
tests_manual/               # تست‌های end-to-end با یه FakeSession جعلی (بدونِ نیاز به توکنِ واقعی)
docs/                       # راهنماهای تفصیلی
```

## اجرای تست‌ها

تست‌ها یه بات فیک (`FakeSession`) دارن که همه‌ی تماس‌های API تلگرام رو شبیه‌سازی
می‌کنه — یعنی نیازی به توکنِ واقعیِ ربات یا اتصال به اینترنت نیست، فقط یه
PostgreSQL محلی لازمه.

```bash
export DATABASE_URL="postgresql+asyncpg://postgres:postgres@localhost/kasbokar_test"
export MAIN_BOT_TOKEN="123456789:AAtestFAKEtokenFAKEtokenFAKEtokenFAKE"
export ENCRYPTION_KEY="$(python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())')"
export ADMIN_TELEGRAM_IDS="12345"
export WEBHOOK_BASE_URL="https://example.com"
export RUN_MODE="polling"
export AUTH_MODE="test"

alembic upgrade head   # روی دیتابیسِ تست هم باید مایگریشن اجرا بشه
python3 tests_manual/run_all_tests.py
```

مجموعاً **۱۴ فایلِ تست، ۴۵ تستِ جداگانه**، همه علیه دیسپچرها و هندلرهای واقعیِ
پروژه (نه موک‌های سطحی) اجرا می‌شن. برای جزئیاتِ کاملِ اینکه کدوم تست چی رو
پوشش می‌ده، `docs/local-testing-guide.md` رو ببین.

## نکاتِ مهمِ معماری

- **هر فروشگاه یه توکنِ ربات مجزا داره.** فروشگاه‌دار از طریقِ پنلِ ربات اصلی
  توکنش رو (که از BotFather گرفته) وارد می‌کنه؛ سیستم اعتبارسنجیش می‌کنه
  (با یه `getMe` واقعی) و رمزنگاری‌شده (Fernet) ذخیره‌ش می‌کنه.
- **مشتری‌های نهایی هیچ‌وقت مستقیم با ربات اصلی حرف نمی‌زنن.** اونا فقط با
  رباتِ اختصاصیِ همون فروشگاه در ارتباطن؛ وقتی چیزی (مثلاً عکسِ رسید) باید به
  فروشگاه‌دار برسه، از طریقِ *ربات اصلی* فوروارد می‌شه، نه رباتِ فروشگاهی
  (چون فروشگاه‌دار با ربات اصلی چت می‌کنه).
- **`file_id`های تلگرام بینِ دو نمونه‌ی Bot متفاوت قابل‌انتقال نیستن.** برای
  همین وقتی عکسِ مشتری باید به فروشگاه‌دار فوروارد بشه، اول با نمونه‌ی رباتِ
  فروشگاهی دانلود می‌شه و بعد به‌صورتِ یه فایلِ تازه (`BufferedInputFile`) با
  نمونه‌ی ربات اصلی آپلود می‌شه.
- **پیام‌های پشت‌سرهمِ مشتری debounce می‌شن** (پیش‌فرض ۳ ثانیه، حداکثر ۱۰ ثانیه
  انتظار) تا چند پیامِ جدا (مثلاً «سلام» و بعد سوال) یه‌جا و با یه جواب پردازش
  بشن، نه با چند جوابِ جدا.
- **پرداختِ کارت‌به‌کارت یه مبلغِ منحصربه‌فرد می‌گیره** (چند تومان پسوندِ
  تصادفی) تا فروشگاه‌دار بتونه واریزیِ بانکیِ واقعی رو با پرداختِ در انتظار مچ
  کنه؛ زرین‌پال چون callback خودکار داره به این نیاز نداره.
